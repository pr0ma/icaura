# ICAura MQTT — Android

Мобільний застосунок для моніторингу через контролер **ICAura** . Застосунок отримує дані з MQTT-брокера, тож працює з будь-якого місця, де є інтернет, без прямого доступу до локальної мережі з ICAura.

Оформлення повністю повторює веб-інтерфейс ICAura: та сама схема потоків енергії, плашка АКБ, плитки та енергозвіт.

## Можливості

- **Енергія**: анімована схема потоків Мережа / PV / АКБ / Навантаження, режими виходу й заряду, температури, детальні плитки PV, навантаження й мережі.
- **АКБ**: SOC, напруга, струм, потужність, стадія заряду (Bulk / Float), уставки. Джерело даних визначається автоматично: реальна BMS (CAN/UART), віртуальна BMS ICAura або оцінка інвертора.
- **Енергозвіт** за день, місяць або рік: вироблено PV, спожито, імпорт і віддача в мережу, автономність, фінанси за вашим тарифом.
- **Моніторинг**: усі датчики інвертора, згруповані за розділами.
- **Налаштування інвертора**: перегляд поточних значень і запис через MQTT (вмикається окремо).
- **Віртуальна BMS**: запуск і скасування примусового заряду до 100 %.
- Світла й темна теми (за системними налаштуваннями).
- Підключення через **TCP, TLS, WebSocket і WebSocket TLS**, з логіном і паролем.

## Вимоги

- Android 7.0 (API 24) або новіший.
- Контролер ICAura з увімкненою публікацією MQTT (вкладка **MQTT**, потрібен рівень доступу 2).
- MQTT-брокер, до якого мають доступ і ICAura, і телефон (наприклад, Mosquitto).

## Встановлення

Завантажте https://github.com/pr0ma/icaura/raw/refs/heads/main/ICAuraMQTT.apk і встановіть на телефон. Для цього потрібно дозволити встановлення з невідомих джерел.

## Налаштування

### 1. ICAura (веб-інтерфейс → вкладка MQTT)
- Увімкніть відправку по MQTT і вкажіть адресу брокера.
- Запам'ятайте **базовий топік** <base> (`icaura/<mac>`). Де <mac> це MAC адрес вашого ESP32
- Для запису налаштувань з телефону ввімкніть **«Дозволити керування»**.

### 2. Застосунок (вкладка «Підключення»)

| Поле | Значення |
|---|---|
| Протокол | TCP, TLS, WebSocket або WebSocket TLS |
| Адреса, порт | адреса брокера; типові порти 1883 / 8883 / 8080 / 8084 |
| Шлях WebSocket | зазвичай `/mqtt` (лише для WS і WSS) |
| Логін, пароль | облікові дані брокера |
| Базовий топік | такий самий, як в ICAura |
| Не перевіряти сертифікат | для самопідписаних сертифікатів |
| Керування | дозволяє запис налаштувань інвертора |

## MQTT-топіки

| Топік | Напрям | Вміст |
|---|---|---|
| `<base>/state` | ICAura → застосунок | JSON з усіма датчиками, `link`, `age`, `rssi`, `uptime`, `vbms_*` |
| `<base>/status` | ICAura → застосунок | `online` / `offline` (retained, Last Will) |
| `<base>/settings` | ICAura → застосунок | JSON з поточними налаштуваннями інвертора |
| `<base>/set/<параметр>` | застосунок → ICAura | нове значення параметра, наприклад `bat_bulk_volt` = `27.6` |
| `<base>/set/vbms_force` | застосунок → ICAura | `1` запустити, `0` скасувати примусовий заряд |
| `<base>/set_result` | ICAura → застосунок | результат запису: `ok`, `changed`, `value`, `error` |

Межі значень і всі перевірки виконує ICAura, ті самі, що й у веб-інтерфейсі. Скидання до заводських налаштувань через MQTT не приймається.

## Обмеження

- З'єднання з брокером тримається лише поки застосунок відкритий. Фонових сповіщень немає.
- Графік відключень і час інвертора не передаються по MQTT, тому в застосунку їх немає.
- Для віртуальної BMS показується режим, спожиті Ач і SOC. Поріг повернення уставок і прогрес «до повної» доступні лише у веб-інтерфейсі.
